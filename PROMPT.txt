客户那边的供应商质量工程师给我们提了个要求：来料检验的抽样方案要能拿出 OC 曲线和风险数据说话，不能再只是一句「按 GB 2828 执行」。我们质量部现在的做法是查表加手算，一次抽样还好，二次抽样的接收概率和平均样本量基本算不清。所以打算做一个抽样方案服务，把方案存成档，按档出曲线、出风险，也能根据风险要求反过来设计方案。

「方案档」有名字，保存到数据库，分两类。一次抽样：样本量 n、接收数 c。二次抽样：第一样本 n1、接收数 c1、拒收数 r1，第二样本 n2、累计接收数 c2；要求 c1<r1≤c2+1，否则拒绝。每个档还可以带批量 N；带了 N 就用超几何分布，没带就用二项分布，也可以显式要求泊松近似，这时响应里要标注近似并在 n·p 超过 5 时给出警告。所有组合数和概率都要在对数域计算，n 取到几千也不能溢出或静默变成 0。

对一个档可以请求：给定一组不合格率 p，算接收概率 Pa；二次抽样另给平均样本量 ASN；在带 N 且采用拒收批全检的前提下，给平均出厂质量 AOQ、其最大值 AOQL 及对应的 p，以及平均检验总数 ATI；给定 AQL 和 LTPD，算生产方风险 α=1−Pa(AQL) 和使用方风险 β=Pa(LTPD)。曲线请求可以指定 p 的范围和点数，点数上限 500。

方案设计：给 AQL、α、LTPD、β，搜索满足两个风险约束且 n 最小的一次抽样方案，n 相同时取 c 较小者；二次抽样设计限定 n2=n1 或 n2=2·n1，在满足约束的方案里取 p=AQL 处 ASN 最小的一个。搜索范围有上限，找不到时明确返回「无可行方案」。

需要测试证明：p=0 时 Pa=1；p=1 且 c<n 时 Pa=0；n 固定时 c 增大，整条 Pa 曲线不下降；c 固定时 n 增大，任意 0<p<1 处 Pa 下降；N 趋于很大时超几何结果逼近二项；把二次抽样的 n2 设为 0、c1=c2、r1=c1+1，结果与同参数的一次抽样完全相同；ASN 介于 n1 与 n1+n2 之间；ATI 介于 n 与 N 之间；AOQL 不小于曲线上任何一点的 AOQ；设计出的一次方案满足约束，且样本量减一后在任何 c 下都不再满足。n<1、c<0、c≥n、p 不在 [0,1] 内、N 小于样本量、AQL 不小于 LTPD、风险不在 (0,1) 内，都要拒绝并说明是哪个字段。方案档支持新建、修改、删除和按名查询；多个请求同时读写不同档，互不影响。

用 Go 1.23 + Echo。分布计算（含对数域组合数）、一次与二次抽样的 OC/ASN、AOQ 与 ATI、风险计算、方案搜索、方案档存储、HTTP 层分包。方案档存 PostgreSQL 16。go test 覆盖以上性质，另附 n=80、c=2 的一次方案作为可手算的例子。服务镜像用 golang:1.23-alpine 构建，与 postgres:16-alpine 以 Docker Compose 一起起来；只提供 HTTP 接口，不需要前端。
